## 审核方案 

### 方案一：标准 AI 审核 + 用户决策闭环 

此方案侧重于 AI 的全面诊断与用户的终审权，适用于需要快速扫描全篇风险或用户对法律细节把控严格的场景。

#### 1. 流程架构设计 

- 

  前置拦截：跳过自定义规则解析，直接进入全量条款切分与专家模型审核。

- 

  N7 结构化提取：强制输出包含 `bbox`（坐标）、`risk_level`（风险等级）的标准 JSON。

- 

  N8 可视化与交互：将 N7 的数据转化为前端可渲染的指令，实现“所见即所得”的标红与采纳。

#### 2. 结构化输出与标红逻辑 

在 **N7 结构化报告生成器** 阶段，系统需严格生成以下数据格式，以供前端精准定位：

```
{
  "clause_title": "违约责任条款",
  "text_location": {
    "page": 3,
    "bbox": [120, 450, 480, 470]   // 🔴 关键坐标，指示文本在页面中的具体位置
  },
  "risk_level": "High",            // 🔴 High/Medium/Low，用于驱动前端颜色渲染
  "ai_suggestion": "违约金上限不得超过实际损失的30%，建议修改。",
  "source": "AI_AUTO"
}
```

**标红渲染（N7.5）**：前端读取 `bbox` 坐标，在文档预览区绘制红色高亮框；读取 `risk_level`，分别填充红（High）、黄（Medium）、蓝（Low）背景色。

#### 3. 交互闭环设计 

**N8 交互控制台** 是用户行使决策权的核心界面（参考 UI 截图）：

**操作矩阵**：

- 

  **接受**：AI 建议直接写入修订版合同，系统记录“已采纳”。

- 

  **修改**：用户编辑建议内容，系统记录“已修改”。

- 

  **不接受**：该条款移入“忽略列表”，不纳入最终修订范围。

所有输出物（审查意见书、修订版合同批注）中，必须附带 `source_tag` 字段，确保每一处修改都有据可依。

### 方案二：自定义规则主导 + 灵活双审模式 

此方案侧重于用户预设的业务红线，AI 仅作为辅助验证工具，适用于企业内部风控标准极其明确的场景。

#### 1. 流程架构设计 

**决策树节点（新增 N1.5）**：在用户配置完自定义规则后，系统引入一个 **二次确认节点（N1.5）**。

- 

  **分支 A（纯规则模式）**：仅按用户规则审核，不调用 AI 大模型，响应速度最快。

- 

  **分支 B（双审模式）**：先按用户规则审核，再触发 AI 标准审核。

#### 2. 双重判断逻辑 

**第一阶段：人工规则审核**

- 

  输入：用户上传的《自定义审核规则文档》。

- 

  处理：系统仅检索用户指定的条款类型（如“知识产权归属”），并严格按照用户设定的阈值（如“违约金不得超过20%”）进行判断。

**第二阶段：条件判断（是否启动 AI 二次审核）**

- 

  触发逻辑：在 N1.5 节点，若用户勾选“需要 AI 二次审核”，则系统进入 **方案一的 AI 审核流程**；否则，直接进入 **结论聚合层**。

#### 3. 结论聚合与溯源（N7 增强） 

在 **N7 结论聚合 Agent** 中，系统需对不同来源的意见进行归因分析，并在最终报告中明确标识。

#### 4. 防呆设计 

**规则锁定机制**：一旦用户选择“直接执行”（纯规则模式），系统会在底层逻辑中锁定 AI 的权重。即使后续 AI 给出相反建议，系统也会将其标记为“仅供参考”，防止 AI 过度干预用户的强制标准。

------

### 架构落地建议 

- 

  **状态机管理**：建议在 LangGraph 中增加一个 `review_mode` 状态变量，取值为 `{ AUTO, CUSTOM_ONLY, DUAL }`，下游节点（如 N6 检索、N7 聚合）根据该状态动态调整提示词（Prompt）。

- 

  **溯源标签**：在所有输出物（审查意见书、修订版合同批注）中，必须附带 `source_tag` 字段，确保每一处修改都有据可依。

### 第一层：意图路由 + 审核模式选择（⚠️ 关键重构） 

#### [N1 意图识别 + 审核模式分发器] 

**两层判断架构**

```
用户上传合同 + 规则+文字指令
 ↓
[N1 意图路由]
 ↓
 先判断是哪种任务，是合同审核再判断哪种审核方式
 ↓
 ├─ AI_AUTO → 跳过规则解析，直接 N5-A
 │
 └─ CUSTOM_RULES → 进入 [N1.5 策略确认]
                     ↓
                     询问用户：
                    "是否启用 AI 二次审核？"
                     ↓
                    ├─ 否 → enable_ai_second_review = false
                    └─ 是 → enable_ai_second_review = true
                     ↓
                     这两个值写入 State，贯穿全流程
```

**输入**：用户指令、上传文档、可选：自定义规则文本 / 规则文件

**输出状态（State）**：

```
{
  "intent": "contract_review",   // 或文书生成/辩论
  "review_mode": "AI_AUTO | CUSTOM_RULES",
  "custom_rules": null | {...},
  "enable_ai_second_review": false,
  "user_rules_evaluation": null
}
```

**若上述意图结果是 合同审核**：

- 

  ✅ **分支 A：标准 AI 审核（方案一）**

  - 

    用户未上传规则，或明确选择「AI 审核」

  - 

    ➡ 设置：`review_mode = "AI_AUTO"`, `custom_rules = None`

- 

  ✅ **分支 B：自定义规则审核（方案二）**

  - 

    用户上传规则，或选择「按我的规则审核」

  - 

    ➡ 进入 **[N1.5 规则配置与二次审核确认]**

    - 

      功能：解析用户规则（可能是选择文字输入规则，或者对上载的文件进行初次分辨）；询问是否启用 AI 二次审核；锁定主审核逻辑

    - 

      交互内容：

      ```
      请确认审核方式：
      ✅ 仅按自定义规则审核（不使用 AI）
      ✅ 自定义规则为主 + AI 二次审核
      ```

    - 

      输出：

      ```
      {
        "review_mode": "CUSTOM_RULES",
        "enable_ai_second_review": true | false
      }
      ```

### 第二层：合同预处理（不变） 

#### [N2 文档解析引擎（可复用）] 

一个可复用、多模态、结构化的文档提取器。

PDF / Word / 扫描件 OCR。

主要是进行文字和图片等内容提取。

N1 是"收文件"，N2 是"拆文件"。

N2 把一份合同拆解成文字、表格、图片、印章、批注等所有可识别元素，每个元素都贴上精确的坐标标签，然后打包成一个标准 JSON 交给下游。

（初步进行数据处理）

**方案一：添加不同组件使其可识别多种信息**

```
N2 文档解析引擎（可复用）
│
├─ 2.1 格式适配层（Format Adapter）
│    · 识别文件类型 → 路由到对应解析器
│    · PDF / Word / Excel / 图片 / 扫描件
│
├─ 2.2 多模态提取层（Multimodal Extractors）
│    ├─ TextExtractor → 正文文字 + 样式 + 坐标
│    ├─ TableExtractor → 表格结构 + 单元格坐标
│    ├─ ImageExtractor → 嵌入图片 + 分类
│    ├─ StampDetector → 印章/签名检测
│    ├─ OCRExtractor → 扫描件文字识别
│    ├─ LayoutAnalyzer → 版面分析（阅读顺序）
│    └─ AnnotationExtractor → Word批注/修订痕迹
│
├─ 2.3 统一结构化输出层（Schema Normalizer）
│    · 将所有提取结果统一为 N2Output Schema
│    · 每个元素带 page + bbox
│
└─ 2.4 语义分块层（Semantic Chunker）
     · 按条款/段落/表格边界切分
     · 输出带坐标的语义块 → 供 N4 使用
```

发生在"用户规则审核之前"，而不是之后。它是一个前置的策略选择，而不是后置的补救动作。

```
enable_ai_second_review == true ?

        在规则审核结果基础上再跑 AI 审核

```


- 

  AI 给出的意见

- 

  AI+人工共同的意见

- 

  AI 人工意见冲突 → 展示不同的审核意见

#### [N9a 低风险] 自动生成修订合同 

- 

  **闭环交付，不止于"发现问题"**：没有修订版合同，系统只是个"挑错工具"；有了它，系统是"解决问题的工具"。

- 

  **立场化生成**：

  - 

    甲方视角：强化甲方权利、弱化甲方义务

  - 

    乙方视角：反之

  - 

    同一份审核结果，生成两份立场不同的修订版

- 

  **保留修改痕迹（可选模式）**：

  - 

    清洁版：直接输出改好的合同，无痕迹

  - 

    修订痕迹版：类似 Word 的"跟踪更改"，红色删除线 + 绿色新增，律师一眼看出改了哪里

-
