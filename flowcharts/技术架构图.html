基于真实代码的 LangGraph 编排实现：两级路由 · 7 大可复用子图模块 · 检索子图实例化 3 次 · AgentState 总线 · Checkpointer 持久化

SECTION 01
🏛️ 主图编排
langgraph_main.py：StateGraph(AgentState) 编译主图，7 个业务节点 = 2 个路由节点 + 5 个子图节点；L1 小红书意图 → L2 intent_router → 4 条元路径（contract_compliance / r_retrieval / qa / docgen）；xhs 在 L1 直接命中。
SECTION 02
📄 预处理子图
5 节点纯链：party_identify → contract_classify → full_text_segment → numeric_extract → llm_query_extract。仅由 contract_compliance 编排外壳调用，把文档/文本输入统一结构化。
SECTION 03
🔍 检索子图（9节点）
实体召回 → 精准过滤 → 7 项加权融合；质量门 60(多源)/50(单源) 触发 ≤3 轮重试；三轮仍不达标放行北大法宝付费门禁 interrupt()；企查查资信 L3 收尾。被 contract_compliance / r_retrieval / qa 共享，实例化 3 次。
SECTION 04
⚔️ 双审子图（5节点）
parallel_dual_review 用 ThreadPoolExecutor(max_workers=2) 并发执行合规审查 + 合同 AI 审查；冲突消解 5 规则（合规优先一票否决）→ 59 条 YAML 数值校验 → 三路聚合 → 交付。
SECTION 05
🛡️ 合同合规编排子图
编排外壳：输入归一化管道（input_source_router / doc_extract / doc_empty_guard / text_recognize）→ preprocess → cc_retrieval → dual_review。主图只保留一个节点，内部封装整条链路。
SECTION 06
💬 法律问答子图
4 节点：qa_intent_classify 法律相关性三级分类；法律相关嵌套复用 retrieval 子图（qa_retrieval）；非法律直走 llm_direct_out。subgraph composition 多层嵌套。
SECTION 07
📝 文书生成子图（7节点）
案情分析 → [need_clarify?END] → 模板匹配 → 查询规划 → doc_parallel_retrieve（ThreadPoolExecutor 单节点内并发法条+类案）→ 条款填充 → 风险分析 → 终稿交付。注意：文书生成不调用共享 retrieval 子图，内部检索独立实现。
SECTION 08
📕 小红书发布子图
5 节点：文案生成 → 配图生成 → 图文合规检查 → 自动发布 → Markdown；质检不通过优雅终止 END，不污染主图状态。完全独立于法律推理栈。
SECTION 09
📦 AgentState 状态总线
TypedDict(total=False)，100+ 字段分 9 类。节点仅返回修改字段（partial update），框架自动合并。检索/审查/问答/文书共享同一状态总线，端到端可追溯。
SECTION 10
🗄️ 基础设施层
FAISS(bge-m3) 五域向量 + Neo4j 图谱 + 7 项加权融合；SqliteSaver 磁盘 Checkpointer；北大法宝/企查查 MCP；MinerU 解析；FastAPI/Streamlit。

SECTION 02

📄 预处理子图（5 节点 · 纯链）

preprocess_subgraph.py：拿到归一化后的 doc_text 后，按 party_identify → contract_classify → full_text_segment → numeric_extract → llm_query_extract 五节点串联做结构化预处理。输出 party_a / party_b / user_side / contract_type / doc_segments / extracted_numerics / retrieval_query / retrieval_keywords 等字段，供下游检索与审查复用。本子图不直接挂载在主图，而是作为嵌套子图由 contract_compliance 编排外壳在入口调用。

💡 点击节点查看每个预处理步骤写入的状态字段与下游消费方。
SECTION 03

🔍 检索智能体子图（9 节点 · 三阶段 + 质量门重试环）

retrieval_subgraph.py：实体召回层（Neo4j Cypher 4 类 UNION ALL + 5 域 FAISS + 关键词扩展，按 7 类检索意图做数据源/关系偏置）→ 精准过滤层 → 融合排序层（7 项加权融合：图谱 0.30 / 向量 0.20 / 权威 0.20 / 精准 0.15 / 跳转·法律层级·案例层级各 0.05）。质量门 quality_score 阈值 60（多源）/50（单源）触发回退重试（≤3 轮）；三轮仍不达标才放行 北大法宝付费门禁（interrupt() 真中断），企查查资信在 L3 收尾调用，最后 context_pack 打包检索上下文供下游复用。注意：共享检索子图仅被 contract_compliance / 独立检索（r_retrieval）/ 法律问答（qa_retrieval）三条链路复用，实例化 3 次；文书生成子图内部使用独立的 doc_parallel_retrieve，不调用本子图。

💡 点击节点查看每阶段技术选型与融合策略；橙色虚线为质量门重试回边。
SECTION 04

⚔️ 双审子图（5 节点 · 并行双审 + 冲突消解）

dual_review_subgraph.py：风险审查核心，被 contract_compliance 编排外壳以 add_node 调用。parallel_dual_review 用 ThreadPoolExecutor(max_workers=2) 并发执行合规审查与合同 AI 审查（串行约 20s → 取较慢者约 12s，省约 40%）。两路写入不同 state 字段无竞态。合同双审走 conflict_resolution（5 规则合规优先一票否决）→ numeric_validate（59 条 YAML 确定性校验）→ risk_aggregate（三路聚合 + 对立方加权）→ final_delivery；合规单审跳过冲突消解直走数值校验。

💡 点击节点查看并行安全设计、5 条冲突消解规则与 can_sign 三态；紫色虚线为并发分支。
SECTION 05

🛡️ 合同合规编排子图：编排外壳（4 节点输入管道 + 3 个嵌套子图）

contract_compliance_subgraph.py：合同/合规任务的自包含编排外壳，把"输入归一化管道 + 共享预处理 + 检索复用 + 双审内核"封装为一个独立编译的子图，主图只通过 add_node("contract_compliance", ...) 调度。内部结构：输入归一化管道 4 节点（input_source_router → doc_extract → doc_empty_guard / text_recognize，空/损坏/非合同拦截直接 END）→ preprocess 子图（5 节点结构化预处理）→ cc_retrieval 子图（复用 9 节点检索底座）→ dual_review 子图（5 节点风险审查核心）→ END。该设计让主图从 13 节点精简到 7 节点，体现"薄编排、厚子图"的 subgraph composition 思想。

💡 点击节点查看输入归一化、空/损坏守卫、子图嵌套调度与面试问答。
SECTION 06

💬 法律问答子图（4 节点 + 嵌套检索子图）

qa_subgraph.py：qa_intent_classify 做法律相关性三级分类；法律相关 qa_retrieval 直接嵌套复用 retrieval 子图（subgraph composition 多层嵌套），非法律直走 llm_direct_out。图谱查询失败自动降级 RAG 兜底，覆盖法条/判例/制度多类咨询。

💡 点击节点查看嵌套子图复用方式与降级策略。
SECTION 07

📝 文书生成子图（7 节点 · 并发检索 + 澄清守卫）

docgen_subgraph.py（V6）：案情分析 → 模板匹配 → 查询规划 → doc_parallel_retrieve（ThreadPoolExecutor 单节点内并发跑法条 + 类案检索，字段互不冲突合并回写）→ 条款填充 → 风险分析 → 终稿交付。澄清守卫：need_clarify 时直接终止生成并返回追问文案，杜绝残缺文书。注意：文书生成链路不调用共享的 retrieval_subgraph，其法条/类案检索由本子图内部独立的 doc_law_retrieve_node / doc_case_retrieve_node 在 doc_parallel_retrieve_node 中并发调用，避免与通用检索底座耦合。

💡 点击节点查看并发检索设计、澄清守卫的 bug-fix 背景与交付物。
SECTION 08

📕 小红书发布子图（5 节点 · 独立自动化链路）

xhs_subgraph.py：完全独立于法律推理栈，封装图文生成与自动发布。链路：xhs_text_generate → xhs_image_generate → xhs_check_text_image → [pass] → xhs_auto_publish → xhs_generate_markdown → END；质检不通过直接优雅终止（fail → END），不污染主图状态。

💡 点击节点查看小红书链路如何与法律推理栈解耦。
SECTION 09

📦 AgentState 状态总线（TypedDict · 100+ 字段 · 9 类）

agent_state.py：所有节点共享的 TypedDict(total=False) 状态容器，100+ 字段分 9 大类别。节点仅返回其修改的字段（partial state update），框架自动合并到全局 state；可用 Annotated[type, reducer] 自定义合并（列表追加 / 集合并集）。检索、审查、问答、文书通过同一总线实现端到端可追溯。

💡 点击中心节点或任意类别查看字段清单与读写职责。
SECTION 10

🗄️ 基础设施层（共享底座）

被所有子图共享的底层能力：向量检索（FAISS + bge-m3，五域 laws/regulations/cases/industry_sources/interpretations）、知识图谱（Neo4j Cypher 实体查询）、7 项加权融合（图谱/向量/权威/精准/层级）、确定性 YAML 规则引擎、SqliteSaver 磁盘 Checkpointer、北大法宝/企查查 MCP 工具、MinerU 多模态解析、FastAPI(SSE) 与 Streamlit 前后端。
