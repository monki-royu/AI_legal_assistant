🏛️ LangGraph 多智能体总架构

8 智能体协作全景：用户入口 → 小红书前置过滤 → 意图路由 → 企查查统一预查 → 二次路由 → 共享 5 节点预处理 → 检索提前 → 合同审核/合规审查并行 → 冲突消解(合规优先) → 四路风险聚合 → 最终交付。一图掌握全局数据流与复用关系。

L1 · 用户入口
👤L1

用户入口 (Streamlit / FastAPI)

合同文件 / 法律问题 / 检索关键词 / 文书要求 / 小红书内容。输出初始 AgentState{input, uploaded_doc_path,...}。

👆 点击节点查看：作用 / 流转 / 复用 / 设计理由 / 技术选型 / 优化 / 面试题
L2 · 小红书意图前置过滤（所有请求必经）
📱L2

小红书意图识别 (xiaohongshu_publish_intent_node)

LLM 判断用户是否想发小红书：是→走小红书独立链路；否→进入主意图路由。前置过滤(Filter-Before-Route)模式。

👆 点击节点查看：作用 / 流转 / 复用 / 设计理由 / 技术选型 / 优化 / 面试题
L3 · 意图路由（二次分发）
🧭L3

意图路由 (intent_router_node)

LLM 分析输入确定任务类型写入 task_type：contract_review / compliance_review / legal_research / legal_qa / legal_document_gen / case_search / law_query / other。

👆 点击节点查看：作用 / 流转 / 复用 / 设计理由 / 技术选型 / 优化 / 面试题
L4 · 企查查预判定（统一缓存，8 条非小红书路径共享一次）
🏢L4

企查查预判定 (credit_precheck)

所有非小红书路径共享一次企查查预查，避免重复查询。strong→查全部 / medium→查关键词 / weak→仅标记 / none→跳过。

👆 点击节点查看：作用 / 流转 / 复用 / 设计理由 / 技术选型 / 优化 / 面试题
💡 旁批（小白版）：不管走哪条法律链路，先统一查一次对方企业资信（带缓存），后面不用重复查，省钱省时。
L5 · after_credit_precheck_router（二次路由到真实起点）
↓ 按 task_type 分发至：合同审核 / 合规审查 / 法律检索 / 法律问答 / 文书生成 / 案例检索 / 法规查询 / 其他兜底
⭐ 共享数据预处理（5 节点，合同/合规共用）
📄N2

文档提取 (doc_extract_node)

读取 uploaded_doc_path 指向的合同文件（txt/md/docx），检测文件类型并调用对应解析器，提取纯文本写入 doc_text。无文件时用 input 兜底。

👆 点击节点查看：作用 / 流转 / 复用 / 设计理由 / 技术选型 / 优化 / 面试题
💡 旁批（小白版）：律师拿到合同原件的第一件事：把各种格式的纸面/电子版合同变成可阅读的纯文本，后面所有分析都基于这段文本。
👥N8

甲乙方识别 (party_identify_node)

从 doc_text[:3000] + input 识别甲方/乙方名称（规则正则 → LLM 兜底），并推断用户立场 user_side（A甲方/B乙方/关键词）。输出 party_a/party_b/user_side。

👆 点击节点查看：作用 / 流转 / 复用 / 设计理由 / 技术选型 / 优化 / 面试题
💡 旁批（小白版）：律师得先搞清“我的客户是谁、对方是谁”，这决定了后面审查时该帮哪一方挑风险（立场化）。
🏷️N3

合同分类 (contract_classify_node)

LLM 基于全文判断合同类型（买卖/租赁/借贷/建设工程/政府采购/劳动/服务/技术/其他），写入 contract_type。

👆 点击节点查看：作用 / 流转 / 复用 / 设计理由 / 技术选型 / 优化 / 面试题
💡 旁批（小白版）：不同类型的合同，适用的法律、审查重点、模板都不同。比如建设工程合同要看建筑法，劳动合同要看劳动法。
✂️N4

条款切分 (clause_split_node)

按“第X条”编号优先切分；无编号则按换行分段。输出结构化条款列表 doc_clauses=[{id,title,text}]。

👆 点击节点查看：作用 / 流转 / 复用 / 设计理由 / 技术选型 / 优化 / 面试题
💡 旁批（小白版）：律师逐条读合同，先搞清楚结构：哪些条款说付款、哪些说违约、哪些说保密……
🔢N5c-1

数值抽取 (numeric_extract_node)

LLM 抽取合同全部关键数值：单价/数量/总价/税率/违约金比例/利率/保证金/付款比例/期限等，写入 extracted_numerics。

👆 点击节点查看：作用 / 流转 / 复用 / 设计理由 / 技术选型 / 优化 / 面试题
💡 旁批（小白版）：律师做“数字标注”——把合同里所有数字圈出来，后面要检查这些数字是否合理、是否超标。
⭐ 检索已提前到此处！（5 节点子图，被合同/合规/法律检索/文书生成 复用）
🔍①

检索·意图分解 (retrieval_intent_decompose_node)

将原始检索意图拆解为 3-5 个检索子角度/关键词（如“违约金是否过高”→[违约金/违约赔偿/损害赔偿/定金罚则]）。初始化检索上下文。

👆 点击节点查看：作用 / 流转 / 复用 / 设计理由 / 技术选型 / 优化 / 面试题
📚②

检索·基础层 (retrieval_base_layer_node)

多路并行检索：L0 Neo4j 实体精确匹配 → L1 FAISS 向量检索 → L2 本地法规关键词(4级回退) → L3 行业标准 → L4 案例 → L5 司法解释；共享层企查查资信。输出 base_citations。

👆 点击节点查看：作用 / 流转 / 复用 / 设计理由 / 技术选型 / 优化 / 面试题
🔧③

检索·增强查询 (retrieval_enhance_query_node)

当 len(base_citations)<2 时触发：LLM 基于合同正文补充生成相关法条（伪检索兜底），输出 enhance_citations。

👆 点击节点查看：作用 / 流转 / 复用 / 设计理由 / 技术选型 / 优化 / 面试题
💡 旁批（小白版）：基础层没找到够多法条时，让 LLM 凭合同内容“补几条相关法条”，宁可带‘AI生成’标注也别空着。
🔀④

检索·融合排序 (retrieval_fusion_sort_node)

RRF 倒数排名融合多路结果 → 去重 → 冲突消解(新法优于旧法/上位法优于下位法/特别法优于一般法) → 质量分(权威+时效+相关+完整)。输出 citations+quality_score。

👆 点击节点查看：作用 / 流转 / 复用 / 设计理由 / 技术选型 / 优化 / 面试题
📤⑤

检索·输出 (retrieval_output_node)

格式化为 research_context 字符串；质量门禁 quality_score≥0.85 直接输出，否则 ≤3 次重试→北大法宝 MCP 付费兜底/用户确认。

👆 点击节点查看：作用 / 流转 / 复用 / 设计理由 / 技术选型 / 优化 / 面试题
💡 旁批（小白版）：质量够高就直接用（省 MCP 钱）；不够就重试，实在不行再花真钱去北大法宝查，或让用户决定。
⭐ 分支独立执行：合同审核 ≠ 合规审查
两条链路从检索输出后并行展开
📗 合同审核AI（商业律师·立场化）6 大维度：价格付款/交付验收/违约责任/保密IP/管辖争议/终止退出；user_side=A→站甲方，B→站乙方。输出可谈判的 contract_risk_items。
🔴 合规审查（合规律师·客观中立）7 大领域：强制规定/数据合规/反垄断/税务/劳动/行业准入/政府采购。输出刚性 compliance_risk_items + can_sign。
⚡ 冲突消解节点（新增，合规优先）
🔀⚡

冲突消解 (conflict_resolution)

合规优先原则：①合规 critical→no；②合规 high→conditional（即使合同说可接受也要改）；③同问题双重发现以合规为准；④合规过+合同有风险→保留商业风险；⑤结论冲突以合规为准。输出 merged_risk_items+can_sign。

👆 点击节点查看：作用 / 流转 / 复用 / 设计理由 / 技术选型 / 优化 / 面试题
💡 旁批（小白版）：这是“裁判”环节：商业律师（合同审核）说能签，合规律师（合规）说违法——以合规为准，因为合规有一票否决权。
✔️🔢

数值校验 (numeric_validate_node)

确定性规则引擎（threshold/range/sum_equals），无 LLM 调用，比对法定阈值（已有 citations）。输出 numeric_risk_items。

👆 点击节点查看：作用 / 流转 / 复用 / 设计理由 / 技术选型 / 优化 / 面试题
🏢🏢

资信查询 (credit_check_node)

3-tier 降级 MCP Bearer→AppKey+MD5→Mock（永不阻塞）。10 维度工商/股东/失信/被执行/异常/处罚/司法协助/知产/年报。输出 credit_risk_items+credit_score。

👆 点击节点查看：作用 / 流转 / 复用 / 设计理由 / 技术选型 / 优化 / 面试题
⚠️⚖️

风险聚合 (risk_aggregate_node)

合并合同+合规+数值+资信四路；去重→加权→扣分制(0-100)→等级(Low/Medium/High)。合规 critical 不可降级。

👆 点击节点查看：作用 / 流转 / 复用 / 设计理由 / 技术选型 / 优化 / 面试题
📦OUT

最终交付 (final_delivery_node)

纯字符串拼装 Markdown 报告（无 LLM）：合规结论→合规风险清单→商业风险清单→数值校验→资信→综合评分处置。输出 final_report_markdown+output。

👆 点击节点查看：作用 / 流转 / 复用 / 设计理由 / 技术选型 / 优化 / 面试题
💡 旁批（小白版）：最后把四路结果拼成一份人能看懂的报告：先说“能不能签”，再列风险清单，最后给评分和处置建议。
🧱 模块解耦检索 5 节点子图被合同审核/合规审查/法律检索/文书生成 4 条链路复用
🔒 确定性门禁数值校验用 Python 规则(阈值/范围/求和)，不依赖 LLM
🔄 弹性重试Cypher 校验失败重试≤3次；企查查 MCP 三级兜底(Bearer→AppKey→Mock)
⚡ 冲突消解合规 critical→no；high→conditional；同问题以合规为准
🏢 企查查MCP统一预判定+缓存，10 维度资信，永不阻塞
📊 四路聚合条款+合规+数值+资信，合规 critical/high 不降级

🧩 LangGraph 多智能体总架构 · 节点复用与总架构协作

整个系统由 8 大智能体 协作，核心是 “检索提前 + 节点复用 + 冲突消解” 三件事：

被复用节点被哪些链路复用复用价值
共享数据预处理 5 节点合同审核、合规审查同一份合同只解析/识别/切分/抽数一次
检索 5 节点子图合同审核、合规审查、法律检索、文书生成检索提前到审核之前，三审都能引用法条；被 4 链路复用
冲突消解节点合同审核（内嵌）、合规审查（独立 pass-through）统一“合规优先”裁决，避免重复实现
数值校验 / 资信查询 / 风险聚合 / 最终交付合同审核、合规审查四路风险合并逻辑共用，报告模板共用
企查查 MCP 资信总架构预判定 + 各链路资信查询统一缓存一次查询，三级降级永不阻塞
HistoryStore 持久化文书生成案情/文书可追溯、可重新生成

协作总架构一句话：用户入口 → 小红书前置过滤 → 意图路由 → 企查查统一预查 → 二次路由 → 共享 5 节点预处理 → 检索提前 → 合同审核(立场化)与合规审查(客观)并行 → 冲突消解(合规优先) → 数值校验 → 资信查询 → 四路风险聚合 → 最终交付。
