OVERVIEW · 全局视角

🏛️ LangGraph 多智能体总架构

7 层分层全景：用户入口 → 小红书意图前置过滤 → 意图路由 → 5 大业务链路分流 → 检索/审核/资信并行 → 四路风险聚合 → 输出交付。一图掌握全局数据流与调用关系。

L1 · 用户入口
👤 L1

用户入口 (Streamlit Web 界面)

合同上传 / 法律问答 / 小红书发布请求 / 法律检索。通过 Streamlit Web 界面或 API 接入，输入文本 + 可选上传文档。

L2 · 小红书意图前置过滤
📱 L2

小红书意图识别 (xiaohongshu_publish_intent_node)

所有请求的第一站。LLM 判断用户是否想发小红书：是 → 走小红书发布链路（文案生成→图片生成→检查→发布→Markdown）；否 → 进入主意图路由。属于"前置过滤"架构模式。

L3 · 意图路由
🧭 L3

意图路由 (intent_router_node)

LLM 识别用户意图，输出 task_type，分流至 5 大业务链路：合同审核 / 合规审查 / 法律检索 / 法律问答 / 其他（LLM直接回答）。条件边 + path_map 路由，确定性分流。

L4 · 5 大业务链路分流
↓ 路由分发至对应业务链路 ↓
📋 合同审核16 节点完整链路 · 四路风险聚合
🛡️ 合规审查精简流程 · 合规刚性不降级
🔍 法律检索5 节点检索链路 · RRF 融合
💬 法律问答Neo4j 知识图谱 · Cypher 重试
📱 小红书发布文案 + 图片 + 自动发布
📝 其他LLM 直接回答兜底
L5 · 核心处理层（按链路不同）
⚙️ L5

合同审核 / 合规审查核心链路

文档提取 → 合同分类 → 条款切分 → 数值抽取 → 合同审核AI（LLM 条款风险审查）→ 合规审查（法律法规对照）→ 数值校验（Python 确定性规则）。三审严格串联，合规刚性不降级。

合同审核与合规审查共用同一链路 · 合规审查在合同分类节点中跳过分类逻辑但仍经过该节点
L6 · 5 阶段检索链路
🔎 L6

检索链路 (5 节点拆分)

意图分解 → 基础层（FAISS 向量检索 + Neo4j 图谱检索）→ 增强查询（行业层 + 条款层）→ 融合排序（RRF 融合 + 去重）→ 输出（法规引用列表）。合同审核和合规审查链路经过此 5 节点后继续进入甲乙方识别→资信查询→风险聚合；法律检索直接进入此链路。

retrieval_intent_decompose → base_layer → enhance_query → fusion_sort → output → party_identify → credit_check → risk_aggregate
L7 · 主体识别 + 资信查询 + 风险聚合 + 交付
👥 L7a

甲乙方识别 (party_identify_node)

LLM 从合同文本中识别甲方/乙方名称，写入 party_a / party_b，同时识别用户立场 user_side。

🏢 L7b

企查查资信查询 (credit_check_node)

调用企查查 MCP API（Bearer Token + JSON-RPC 2.0 + SSE 流式），查询甲乙双方企业资信：工商信息、股东结构、失信记录、被执行人、经营异常、行政处罚。计算资信评分与风险等级。三级兜底：MCP-Bearer → AppKey-MD5 → Mock。

第 4 路风险 · 企查查 MCP
⚠️ L7c

风险聚合 (risk_aggregate_node)

合并四路风险数据：① 合同条款风险 + ② 合规风险 + ③ 数值风险 + ④ 资信风险。去重、定级、计算综合评分 overall_risk_score（0-100）与风险等级 risk_level（Low/Medium/High）。合规 critical/high 级风险不降级。

📦 OUT

输出交付 (final_delivery_node)

组装最终报告：final_report_markdown（Markdown 详细报告）+ output（纯文本摘要）。含风险清单、法规引用、资信摘要、是否需律师复核等字段。每条风险带 source_tag（条款审核/合规审查/数值校验/资信查询），全程审计追溯。

END · 结构化输出 · 审计追溯

AGENT 01 · 合同审核

📋 合同审核智能体

16 节点完整链路：文档提取→分类→切分→数值抽取→AI审核→合规审查→数值校验→5阶段检索→甲乙方识别→企查查资信→四路风险聚合→交付。

四路风险 · 企查查资信 · 立场适配
AGENT 02 · 合规审查

🛡️ 合规审查智能体

精简流程：文档提取→合规审查→数值校验→检索→风险聚合→交付。合规红线刚性，不被商业条款审核结果降级。

合规刚性 · 不降级
AGENT 03 · 检索核心

🔍 检索智能体

5 节点拆分链路：意图分解→基础层（FAISS+Neo4j）→增强查询→RRF 融合排序→结构化输出。可被多个上游 Agent 复用。

5 节点 · RRF 融合 · 可复用
AGENT 04 · 法律问答

💬 法律问答智能体

用户提问→实体抽取→Neo4j 匹配→Cypher 生成/校验/执行→答案生成。Cypher 校验失败重试最多 3 次，超限直接生成答案。

知识图谱 · Cypher 重试 · 降级兜底
AGENT 05 · 小红书发布

📱 小红书发布智能体

前置意图过滤→文案生成→图片生成→质量检查→自动发布→Markdown 报告。检查不通过直接结束，不发布。

前置过滤 · 文案 · 图片 · 自动发布
AGENT 06 · 其他兜底

📝 LLM 直接回答

非上述意图的通用问题，由 LLM 直接生成回答。作为兜底链路确保所有用户输入都有响应。
