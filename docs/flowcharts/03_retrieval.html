AGENT 02 · 检索核心

🔍 检索智能体

5 子节点检索链路（被 4 条链路复用）：意图分解 → 基础层(FAISS+Neo4j+local 多路并行) → 增强查询(LLM 伪检索兜底) → 融合排序(RRF+去重+冲突消解+质量分) → 输出(质量门禁≥0.85 / ≤3次重试 → 北大法宝 MCP 兜底)。📌 检索已提前到数值抽取之后！

检索入口
🔍IN

检索入口 (legal_research / case_search / law_query)

合同审核/合规审查经过预处理后进入；法律检索/案例检索/法规查询直接从检索入口开始（跳过 doc_extract 段）。

👆 点击节点查看：作用 / 流转 / 复用 / 设计理由 / 技术选型 / 优化 / 面试题
🔍①

检索·意图分解 (retrieval_intent_decompose_node)

将原始检索意图拆解为 3-5 个检索子角度/关键词（如“违约金是否过高”→[违约金/违约赔偿/损害赔偿/定金罚则]）。初始化检索上下文。

👆 点击节点查看：作用 / 流转 / 复用 / 设计理由 / 技术选型 / 优化 / 面试题
📚②

检索·基础层 (retrieval_base_layer_node)

多路并行检索：L0 Neo4j 实体精确匹配 → L1 FAISS 向量检索 → L2 本地法规关键词(4级回退) → L3 行业标准 → L4 案例 → L5 司法解释；共享层企查查资信。输出 base_citations。

👆 点击节点查看：作用 / 流转 / 复用 / 设计理由 / 技术选型 / 优化 / 面试题
🔧③

检索·增强查询 (retrieval_enhance_query_node)

当 len(base_citations)<2 时触发：LLM 基于合同正文补充生成相关法条（伪检索兜底），输出 enhance_citations。

👆 点击节点查看：作用 / 流转 / 复用 / 设计理由 / 技术选型 / 优化 / 面试题
💡 旁批（小白版）：基础层没找到够多法条时，让 LLM 凭合同内容“补几条相关法条”，宁可带‘AI生成’标注也别空着。
🔀④

检索·融合排序 (retrieval_fusion_sort_node)

RRF 倒数排名融合多路结果 → 去重 → 冲突消解(新法优于旧法/上位法优于下位法/特别法优于一般法) → 质量分(权威+时效+相关+完整)。输出 citations+quality_score。

👆 点击节点查看：作用 / 流转 / 复用 / 设计理由 / 技术选型 / 优化 / 面试题
📤⑤

检索·输出 (retrieval_output_node)

格式化为 research_context 字符串；质量门禁 quality_score≥0.85 直接输出，否则 ≤3 次重试→北大法宝 MCP 付费兜底/用户确认。

👆 点击节点查看：作用 / 流转 / 复用 / 设计理由 / 技术选型 / 优化 / 面试题
💡 旁批（小白版）：质量够高就直接用（省 MCP 钱）；不够就重试，实在不行再花真钱去北大法宝查，或让用户决定。
📤OUT

检索结果输出

输出 citations + research_context，供上游合同审核/合规审查/文书生成引用，或独立返回给用户。

👆 点击节点查看：作用 / 流转 / 复用 / 设计理由 / 技术选型 / 优化 / 面试题
💡 旁批（小白版）：检索本身也是一条独立服务：用户问“违约金过高怎么算”，直接走检索把法条找出来返回。
🧩 子图复用被合同审核/合规审查/法律检索/文书生成 4 链路复用
🔀 RRF 融合多路排名融合，对分数尺度不敏感
⚖️ 冲突消解新法>旧法、上位法>下位法、特别法>一般法
🚪 质量门禁≥0.85 直接出；否则≤3次重试→MCP 付费兜底
🔧 增强兜底基础层不足2条时 LLM 补法条(标注AI生成)
🏷️ 挂载可控task_type+contract_type 决定挂哪些数据源

🧩 检索智能体 · 节点复用与总架构协作

检索 5 节点子图是整个系统的 复用枢纽：

复用方挂载数据源(mounted_sources)
合同审核laws + industry + cases + interpretations
合规审查laws + industry（侧重强规）
法律检索全部数据源
案例检索仅 cases
法规查询仅 laws
文书生成复用 search() 方法填条款

检索提前的优势：旧架构检索在最后，审核时没法条；新架构检索提前到数值抽取之后，使合同审核AI/合规审查/数值校验都能引用法条与法定阈值，实现“检索增强审核”。
