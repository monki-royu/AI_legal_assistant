┌────────────────────────────────────────────────────────────────────────────┐
│ ④ retrieval_fusion_sort_node (融合排序) — RRF融合+去重+冲突消解          │
│ 【输入】base_citations + enhance_citations                                 │
│ 【逻辑】                                                                  │
│    ┌─ skip_fusion == True?                                                 │
│    │    ├─ Yes → 直接返回(单源直查场景: 案例检索/法规查询)                │
│    │    │         【设计】单源直查不需要融合，保留原始顺序即可              │
│    │    │                                                                  │
│    │    └─ No  → ✨ RRF融合(倒数排名法)                                   │
│    │         ① 对每路结果按相关度降序排名                                  │
│    │         ② RRF公式: score = Σ(1/(rank + 60))                          │
│    │            （60是RRF常数，防止单个高排名支配结果）                      │
│    │         ③ 按RRF总分降序取Top-K                                        │
│    │                                                                      │
│    │         ④ 去重: 按(title + article_no + content[:40])做hash          │
│    │                                                                      │
│    │         ⑤ 冲突消解(4条规则):                                         │
│    │           - 新法优于旧法(按颁布年份)                                   │
│    │           - 上位法优于下位法(宪法>法律>法规>规章)              │
│    │           - 特别法优于一般法(如知识产权法>民法典)                   │
│    │           - 同一内容取最完整(字符数多的优先)                           │
│    │                                                                      │
│    │         ⑥ 质量分计算(4维度加权):                                     │
│    │           - 来源权威性(Neo4j+5 / FAISS+3 / local+2 / LLM+0)          │
│    │           - 时效性(在有效期+5)                                        │
│    │           - 相关性(匹配度+3)                                          │
│    │           - 完整性(全文+2)                                            │
│    │           quality_score = (authority+timeliness+relevance+fullness)/15 │
│    │                                                                      │
│ 【输出】state[\"citations\"] — 融合排序后最终结果列表                       │
│         state[\"quality_score\"] — 质量分(0-1)                             │
│         state[\"fusion_log\"] — 融合日志(调试用)                            │
└─────────────────────────────┬──────────────────────────────────────────────┘

│ ⑤ retrieval_output_node (格式化输出) — 质量门禁+最终格式                 │
│ 【输入】citations + quality_score                                          │
│ 【逻辑】                                                                  │
│   ① 将citations格式化为下游可读字符串                                     │
│      research_context = [                                                  │
│        \"【民法典·第585条】当事人可以约定一方违约时...\",                    │
│        \"【合同法司法解释(二)·第29条】当事人主张约定的违约金过高...\",        │
│        ...                                                                 │
│      ].join(\"\\n---\\n\")                                                    │
│   ② 质量门禁(Quality Gate):                                               │
│      quality_score >= 0.85 ?                                              │
│        ├─ Yes ✅ → 直接输出,跳过MCP付费兜底                                │
│        │            【设计】质量足够高，不需要额外花费MCP查询费用           │
│        │                                                                  │
│        └─ No  → quality_retry_count++                                     │
│                  retry_count < 3 ?                                        │
│                    ├─ Yes 🔄 → 回退到②基础层重试(调整检索策略)             │
│                    │           【重试环】最多3次                            │
│                    │                                                        │
│                    └─ No  → ⚠️ 人类介入提示                                 │
│                              ├─ 用户确认 → 北大法宝MCP付费兜底              │
│                              │   【付费降级】调用北大法宝API付费查询         │
│                              └─ 用户拒绝 → 返回现有结果不变                 │
│                                    【安全降级】总比没有好                   │
│                                                                          │
│ 【输出】state[\"research_context\"] — 格式化后的检索结果字符串              │
│         state[\"quality_score\"] — (可能更新后的)质量分                      │
│         state[\"quality_retry_count\"] — 重试次数                           │
│                                                                          │

📌 【被3条链路复用】
   ① 合同审核 → 通过contract_ai_review引用检索结果(商业风险审查)
   ② 合规审查 → 通过compliance_review引用检索结果(合规性判断)
   ③ 法律检索 → 直接从检索入口开始(跳过doc_extract段)

📌 【检索提前的优势】
   旧: doc_extract → classify → clause_split → extract → review → compliance
       → validate → ⏪ 检索(最后才检索)
   新: doc_extract → classify → clause_split → extract → ⭐检索⭐ →
       review(有法条!) → compliance(有法规!) → validate(有阈值!)

📌 【挂载数据源(mounted_sources)控制】
   由task_type + contract_type决定挂载哪些数据源:
   - contract_review → 挂载laws+industry+cases+interpretations
   - compliance_review → 挂载laws+industry(侧重强规)
   - legal_research → 挂载全部数据源
   - case_search → 只挂载cases
   - law_query → 只挂载laws
