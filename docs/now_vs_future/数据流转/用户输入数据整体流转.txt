数据如何流转（完整链路示例）
以 首页智能问答 → "什么是违约金，法律怎么规定的？" 为例：

步骤 1：前端输入
# app.py 中：
input_text = "什么是违约金，法律怎么规定的？"
# 写入 chat_input 组件，点击发送

步骤 2：调用后端 LangGraph
# app.py → _stream_response():
legal_response_stream(input_text, ...)

步骤 3：Intent Router 接收
# intent_router_node.py 接收到的 state：
state = {
    "input": "什么是违约金，法律怎么规定的？",
    "task_type": "",                   # 首页问答 → 空，需 LLM 识别
    "intent_locked": False,            # 首页 → 不锁定
}

# LLM 识别结果 →
return {
    "task_type": "legal_qa",
    "intent_locked": False,
    "mounted_sources": ["*"],
    "skip_fusion": False,
}

步骤 4：检索意图分解
# 检索智能体读取：
state["retrieval_query"] = "什么是违约金，法律怎么规定的？"
state["retrieval_keywords"] = LLM分解输出 → ["违约金", "法律规定"]
state["task_type"] = "legal_qa"
state["mounted_sources"] = ["*"]  # 全源挂载
state["skip_fusion"] = False       # 需要 RRF 融合

步骤 5：检索基础层执行
# L0: Neo4j 实体匹配
_try_entity_match_search("违约金") → 查到民法典第584条（score=1.0）

# L1: FAISS 向量检索 → 补充相关法条（score=0.92）

# L2: 本地法规关键词 → 兜底补充（score=0.7）

# L3: 行业标准 → "违约金"不在行业标准中，跳过

# L4: 案例 → L4.0 Neo4j Case 节点匹配 + L4.3 LLM总结

# L5: 司法解释 → 检索违约金相关解释

# 共享: 企查查 → task_type=legal_qa，不触发

# 结果写入 base_citations

步骤 6：融合排序
# 读取 base_citations + enhance_citations
# RRF 融合 → 去重 → 排序 → 截取前 30 条
# 计算 quality_score = 0.87 (>0.85 ✅ 跳过 MCP)
# 结果写入 citations + research_context

步骤 7：质量门禁
quality_score = 0.87
# >= 0.85 → 达标！直接返回
# 不调用北大法宝 MCP（节省成本）

步骤 8：LLM 答案生成
# LLM 收到 research_context（前8条法条原文）
# + user_input + citations
# → 生成带引用的自然语言答案


步骤 9：前端渲染
# app.py 流式渲染：
# ① 思考过程动画（"📚 检索相关法律条文..."）
# ② 打字机效果输出 LLM 回答
# ③ 引用标注（可点击查看法条原文）
