每个智能体是怎么  "写入状态"到  检索智能体的

2.1 调用方式 — 是"写入状态"
传统编程是 A 调用 B，但在 LangGraph 状态图中，所有智能体是平级节点，通过共享状态 AgentState 通信：

节点A(合同审核) 写入 state["retrieval_query"] = "查询违约金条款"
     │
     ▼ (状态图自动流转到下一个节点)
     │
检索节点 读取 state["retrieval_query"] → 执行检索
     │
     ▼ (状态图自动流转回结果)
     │
节点A(合同审核) 读取 state["citations"] = [...] 
它们通过状态图的条件路由自动串联：


# LangGraph 的核心：条件边
graph.add_conditional_edges(
    "contract_ai_review",           # 合同审核节点执行完后
    contract_router,                # 路由函数决定下一步
    {
        "retrieval_pipeline": "retrieval_intent_decompose",  # → 去检索
        "direct_output": "output_node",                     # → 直接输出
    }
)

2.2 各智能体写入的检索参数
调用方	写入 state 的字段	含义	触发条件
合同审核	retrieval_query="合同中的违约金条款" contract_type="买卖合同"task_type="contract_review"	检索违约金相关法规+行业标准	合同审核节点需要法条依据
合规审查	retrieval_query="数据合规要求" task_type="compliance_review"	检索合规相关法规	合规审查节点需要法规支撑
智能问答	retrieval_query="用户的问题" task_type="legal_qa"	检索与问题相关的法条/案例	问答流程需要 RAG 增强
文书生成	retrieval_query="起诉状相关法条" task_type="legal_document_gen"	检索文书格式/法条依据	文书生成节点需要素材
案例检索页	retrieval_query="用户输入" task_type="case_search"	检索案例	用户直接点击"案例检索"页面
法规查询页	retrieval_query="用户输入" task_type="law_query"	检索法规	用户直接点击"法规查询"页面
