🔍 问题一：「横向按需挂载 + 纵向逐级降级」到底是什么意思？
你的原始构想（图一）
你想的是 8大检索源 → 4种检索方式 对应不同策略：

法律法规 → 实体匹配检索
监管规定 → 关键词+时效过滤
裁判规则 → 图谱查询
企查查 → API结构化查询
…每个数据源独立建知识图谱/Milvus向量库，用各自最优的检索方式
当前实现（图二/三）
当前代码的核心逻辑在 retrieval_base_layer_node.py#L258-L299：


# 纵向：L1 FAISS → L2 本地法规（不足3条降级）→ L3 LLM兜底
# 横向：根据 contract_type 挂载行业增强层
为什么这样做？ 坦诚地说：

数据规模决定了检索架构：你有真实的8大检索源数据吗？如果没有——如果只有AI构造的法律文本和本地TXT——那么为每个源建独立知识图谱就是空中楼阁。FAISS索引是空的、Milvus没有数据、Neo4j图谱是空的——架构再漂亮也查不到东西。
当前策略的工程智慧：
降级 = 不死循环：L1 FAISS查不到 → 降L2本地TXT → 再查不到 → L3让LLM"猜"几条。系统不会挂、不会空指针。这在 retrieval_enhance_query_node.py#L54-L56 体现得很清楚
横向挂载 = 零成本扩展：在 retrieval_base_layer_node.py#L41-L47 中定义映射表，建设合同查住建部、金融查银保监。数据源不存在就跳过，不报错
这不是最终架构，是过渡期最优解。你原始构想的「多知识图谱+多检索引擎」是目标态，当前的「降级+挂载」是跑通链路的工程态。
🏛️ 问题二：企查查资信查询该放哪里？
你的直觉100%正确！ 你的原始想法是对的：企查查应该放在检索智能体的基础层，作为所有智能体可复用的数据源，而不是绑死在合同审核流程里。

当前放置的位置
在 langgraph_main.py#L389-L393：


retrieval_output → party_identify → credit_check → risk_aggregate → final_delivery
它只在合同审核链路中执行。合规审查、法律问答、小红书发布等任务都不会触发资信查询。

应该怎么放？
推荐架构：把资信查询做成检索智能体的一个数据源适配器，按任务类型决定是否调用：


Plain Text

                    ┌─ 合同审核 → 需甲乙方资信 → 调用企查查
检索智能体 ─────────┼─ 合规审查 → 可能需要主体资质 → 可选择性调用
                    ├─ 法律问答 → 视问题而定 → 按需调用
                    └─ 小红书发布 → 不需要 → 不调用
具体做法：在 retrieval_base_layer_node.py 中增加一个「外部数据源适配」分支，让企查查和FAISS、本地法规、行业增强层平级：
# 伪代码示意
if need_credit_check:  # 根据任务类型+用户意图判断
    credit_docs = _try_qichacha_api(parties)  # 企查查API
    citations.extend(credit_docs)
这样做的好处：

合规审查也能查询主体资质（比如招投标合规需要查企业信用）
法律问答涉及企业信息时也能调企查查
符合你说的「供所有其他智能体调用」的设计理念
但为什么现在没这么做？
因为当前各链路还没有对资信查询的需求触发逻辑。合规审查链路没有识别甲乙方的步骤（party_identify_node只在合同审核中执行），所以企查查没有可查询的主体名称。这需要先让各链路都能拿到主体信息，再决定是否调用企查查。

📄 问题三：MinerU 文档解析前瞻架构
你的 MinerU 构想非常专业，这正是企业级 AI 文档系统的标准做法。我来分析当前和理想态的差距：

当前的文档解析
在 doc_extract_node.py：

纯文本提取（txt/md/docx → 字符串）
无结构信息、无坐标、无表格/印章/批注识别
你的理想态

Plain Text

MinerU解析 → 标准JSON（含坐标的文字/表格/印章/批注）
                      ↓
         ┌──── 规则层：正则提取金额/日期/金额/信用代码
         ├──── LLM层：提取语义字段（违约责任、争议解决）
         └──── 融合层：合并+冲突校验
这个方案的价值在于：

坐标定位：每个元素有bbox坐标，报告中可以说「第3页第2段的违约金条款」而不是「合同中提到」
结构化表格：合同表格（如付款计划）不再是文字堆砌，可以按列精确提取
多智能体复用：审核、合规、问答都从同一份JSON按规则+LLM提取各自关心的字段
