当前 · 过渡期

横向挂载 + 纵向降级

基于当前数据规模（AI构造法律文件为主，无真实行业数据）的务实工程选择。用最少的数据跑通完整链路，保证系统鲁棒性。
📊 数据源 & 检索方式
FAISS 向量索引 语义向量检索
本地法规 TXT 关键词匹配
行业增强层 按类型挂载
企查查 API 结构化查询
🔄 检索策略
纵向逐级降级（深度） L1 FAISS → L2 本地法规（不足3条）→ L3 LLM伪检索（不足2条）
横向按需挂载（广度） 建设工程 → 住建部标准；金融借贷 → 银保监会... 根据合同类型动态加载
💡 为什么这样设计？
当前只有法律文本数据，没有足够的行业知识图谱数据。L3 LLM伪检索是为了防死循环/防空指针的兜底。当数据积累充足后，可以逐步升级到右侧的理想架构。
理想 · 目标态

多知识图谱 + 多检索引擎

当积累了足够的真实数据后，为不同数据源构建独立的知识图谱或向量库，针对每种数据源选择最优检索策略——这正是你原始构想的方向。
📊 独立知识图谱 & 向量库
法律法规图谱 实体匹配 + 向量
监管规定图谱 关键词 + 时效过滤
裁判规则/案例图谱 图谱查询 + 向量
行业标准/技术规范 编号精确 + 关键词
企业资信库 API结构化查询
🔄 检索策略
按数据源选最优方式 法条→实体匹配；案例→图谱+向量；标准→编号精确；资信→API结构化查询
并行检索 + RRF融合 多路同时检索 → 归一化打分 → 去重融合 → 按相关性排序
