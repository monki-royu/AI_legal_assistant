# 法智引擎 - 项目架构修改说明与业务架构文档


## 一、项目概述

法智引擎是一款基于 RAG 与多智能体协作架构、面向垂直法律领域的 AI 赋能平台。本项目依据 XMind 主架构图（法智引擎--您的AI法律助理.xmind）实现，使用 LangGraph（兼容层）串联合同审核、合规审查、法律检索、智能问答、小红书发布等智能体节点。

### 2.2 架构修改与调整

#### 修改 1：LangGraph 兼容层
**原因**：当前环境 Python 3.8.5，langgraph 0.0.8 存在 `dict[str, Any]` 语法 bug（需 Python 3.9+），langgraph 0.2+ 要求 Python 3.9+。conda 创建环境受 sandbox 权限限制。

**方案**：自实现 `common/langgraph_compat.py`，API 完全兼容 langgraph（`StateGraph`/`add_node`/`add_edge`/`add_conditional_edges`/`compile`/`invoke`/`ainvoke`/`get_graph`）。未来升级 Python 3.9+ 后，只需把 import 从 `common.langgraph_compat` 切换回 `langgraph.graph` 即可无缝迁移。

#### 修改 2：并行节点串行化
**原因**：XMind 原架构 N5a（合同审核）与 N5b（合规审查）为并行，轻量 StateGraph 用串行模拟。

**方案**：N5a -> N5b -> N5c 串行执行，功能等价，性能差异可接受。

#### 修改 3：Neo4j/FAISS 优雅降级
**原因**：离线环境或 Neo4j/FAISS 索引未构建时，系统不应崩溃。

**方案**：
- 检索节点：FAISS 失败 -> 本地法律文本检索 -> LLM 伪检索
- 知识图谱问答：Neo4j 连接失败 -> 直接 LLM 回答
- 配置文件：`legal_metadata.json` 不存在时降级为空 JSON

#### 修改 4：文档解析方案
**原因**：XMind 原架构推荐 MinerU（方案二），但 MinerU 依赖较重。

**方案**：当前用 zip 解压方式读取 docx（不依赖 python-docx），输出纯文本。后续可无缝切换到 MinerU 获取带 bbox 坐标的标准 JSON。

#### 修改 5：新增小红书发布与智能问答
**依据**：用户要求参考中医项目（ChineseMedicalNewProjectEdit）增添功能。

**实现**：
- 小红书发布：意图识别 -> 文案生成 -> 图片生成 -> 检查 -> playwright 自动发布 -> markdown 展示
- 智能问答：法律问答意图识别 -> 实体抽取 -> Neo4j 匹配 -> Cypher 生成/检查/执行 -> 答案生成

### 4.2 核心数据流

**合同审核流程**：
1. 用户输入合同文本 -> 意图路由识别为 `contract_review`
2. 文档提取 -> 合同分类 -> 条款切分 -> 数值抽取
3. 合同审核 AI（立场+商业条款）-> 合规审查（7大领域）-> 数值校验（YAML规则）
4. 法律检索（FAISS + 本地法律文本 + LLM降级）
5. 风险聚合（三路合并去重 + 加权评分 + 分级）
6. 甲乙方识别 -> 最终交付（结构化报告 + 律师转介）

**知识图谱问答流程**：
1. 用户提问 -> 法律问答意图识别
2. 实体抽取（概念/法规/条文/案件类型）
3. Neo4j 模糊匹配 -> Cypher 生成 -> 安全校验 -> 执行查询
4. 基于检索结果生成答案（无结果时 LLM 降级）

### 4.3 关键设计决策

| 决策 | 原因 |
|---|---|
| 自实现 LangGraph 兼容层 | Python 3.8 环境限制，保证代码可运行 |
| docx 用 zip 解压 | python-docx 未安装，零依赖方案 |
| 三层检索降级 | 保证离线环境也能提供检索能力 |
| YAML 数值校验 | 确定性规则与 AI 审查互补 |
| 风险评分扣分制 | 100分起步，按严重程度扣分，直观可解释 |
